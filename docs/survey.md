# Обзор похожих проектов (2026-11-07)

Цифры скорости в основном взяты у самих авторов и независимо не проверены. Пометка «проверено» означает, что я сам сверился с исходниками.

| Проект | Лицензия | Суть | Что берём |
|---|---|---|---|
| **llama.cpp / ggml** ([github](https://github.com/ggml-org/llama.cpp)) | MIT | Эталон. `--fit`, `--n-cpu-moe`, `--moe-cache-mib` (LRU-кэш экспертов в VRAM, PR #29887, октябрь 2026), MTP/DFlash-спекуляция (**проверено** в исходниках b12189) | Основа движка: загрузчик GGUF, квантованные ядра, CPU-бэкенд, `llama-bench`, `llama-perplexity` |

В гибридном режиме генерация на уровне mainline (около 30–35 ток/с на 5070 Ti), упирается в RAM | Идеи fused-MoE ядер для CPU. `-rtr` для гибрида не использовать |
| **Strata** ([Niko1221/Strata](https://github.com/Niko1221/Strata)) | MIT | Внимание, роутер, общий эксперт и MTP лежат на GPU, остальная VRAM служит кэшем популярных экспертов. **Промахи CPU считает в RAM параллельно с GPU.** MTP до 3 токенов. | **Magnitude** ([magnitudedev/magnitude](https://github.com/magnitudedev/magnitude)) | Apache-2.0 | Около минуты автотюнинга параметров ядер на устройстве, результат кэшируется по связке устройство + toolchain | Модель «скомпилировал один раз — кэшируй». Про MoE-offload ничего |
| **Splash** ([lmstudio blog](https://lmstudio.ai/blog/splash-engine)) | открытый | Только Mac. Отдельный движок под каждую модель: fused-ядра под точные размеры, свой драфт, план памяти | Философия специализации под модель |
| **MetaInfer** (arXiv 2607.12875) | кода нет | Агенты строят и патчат пути адаптации модели под ускоритель, валидация через профилирование | Идея на будущее (облачная генерация ядер) |
| **MLC-LLM** | Apache-2.0 | Компиляция через TVM. Нет выгрузки экспертов MoE в RAM | Мало применимо |
| **TensorRT-LLM** | Apache-2.0 | Поддержка Windows прекращена с v0.18. Нет GGUF и нет выгрузки в RAM | Не применимо |
| **KTransformers** | Apache-2.0 | Выигрыш за счёт AMX/AVX-512 на серверах. У нас их нет | Мало применимо |

Исследования про размещение экспертов: Fiddler (2402.07033, промахи считать на CPU), HOBBIT, MoE-Lightning, ProMoE (предсказательное кэширование), DALI (2602.03495), ATSInfer (2607.10183), SeqMoE (2609.12978, предсказание экспертов и CUDA-graph-совместимый offload).

## Вывод

Идея «держать горячих экспертов на GPU и параллельно считать промахи на CPU» уже известна (Fiddler, Strata). Наше возможное преимущество не в какой-то одной идее, а в том, чтобы **на конкретной машине замерами подобрать и сохранить** всю совокупность: горячий набор под реальную статистику, раздачу потоков по P/E-ядрам, длину драфта MTP, CUDA Graphs. Это и есть «компиляция под железо». Плюс там, где замеры покажут узкое место, сделать точечные ядра под точные размеры модели.
